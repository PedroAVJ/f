The October 7 correction makes new Open Dot provider launches expose local workers as ordinary tools. HyperTUI covers web and remote-state programs only. Its local files/workers/repository pages are rejected in these launches. The historical gateway remains backward compatible for other callers.

Only the migration-owned worker restriction is restored. Claude retains its pre-migration empty built-in tool set and strict MCP configuration; unrelated restrictions and explicit read-only harness settings remain unchanged. Codex no longer receives the migration-wide connector, web-search, or image-tool denials. No legacy tool is disabled without an explicit verified remote replacement record; the current catalog has none.

Bend/N source, manifests, and the author-device signature gate are unchanged. A TypeScript launch overlay corrects the old migration prompts. A narrow ordinary MCP bridge restores worker_list and worker_status using the existing authenticated loopback worker manager; existing mutations still execute through the original worker server and its request gates.

OpenLinear is the existing private deployment. Codex and Claude program bindings use immutable operator-configured CLI adapters and private credentials outside the repository. Remote HTTP actions enforce current-page schemas, exact origin/path scope, explicit redirects, and a streamed 1 MiB body cap.
